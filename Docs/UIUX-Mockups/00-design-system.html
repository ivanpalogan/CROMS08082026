CROMS DESIGN SYSTEM · v2

The same CROMS, refined

Every token below is carried forward from the live UiTheme.cs — the navy sidebar, the accent blue, Segoe UI, 8px button / 10px card radii, the soft two-layer card shadow. Nothing here is a new visual identity; it is the existing one made consistent, given breathing room, and extended with the pieces the current app doesn't have yet (status system, stepper, side panels).

Design philosophy

Four rules every screen in this plan follows.

One task per screen

Show only what the user needs for the step they're on. Everything else moves to a dialog, side panel, or a later step.

Status tells the story

One color+label vocabulary (below) used identically in Marriage, Birth, BREQS, Petitions and Queue — a color never means something different in two modules.

Say the next step

Every workspace states, in plain words, what happens if the primary button is pressed — never a bare "Submit".

Never fake "done"

A disabled control, a blank field and a greyed-out section always mean exactly what they look like — matching CROMS's own long-standing rule against false green ticks.
